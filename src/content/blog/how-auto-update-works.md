在后台填完表单点保存，刷新页面文章就出现了。中间发生的事情其实不复杂。

## 文件就是数据

文章的来源只有一个：`src/content/blog/` 目录里的 Markdown 文件。
网页后台并不维护一份自己的数据，它做的是**把表单内容写成文件**。

```text
src/content/blog/hello-world.md   ->  /blog/hello-world/
src/content/blog/notes/idea.md    ->  /blog/notes/idea/
```

文件名去掉扩展名就是文章 id，也就是网址的一部分。所以「改网址」和「重命名文件」是同一件事，
「删除文章」和「删除文件」也是同一件事。

## 保存时的四步

1. **取出表单内容**：标题、摘要、日期、标签、正文等字段；
2. **校验**：标题必填、日期格式要能解析、文件名不能包含路径穿越字符；
   校验不通过会返回具体原因，页面顶部会逐条列出来；
3. **序列化**：把字段按固定顺序拼成 frontmatter，和正文一起组成完整的 md 文本；
4. **原子写入**：先写临时文件再改名，避免有人在正好读写了一半的文件。

分两步写入的好处是：任何时候打开那个 md 文件，看到的内容都是完整的。

## 访问页面时的三步

1. **扫描目录**：递归找出所有 `.md` 文件，跳过以 `_` 或 `.` 开头的文件；
2. **解析与排序**：解析 frontmatter，按发布日期倒序；frontmatter 有问题的文件会被跳过，
   并在后台首页用红框列出来，而不是让整个网站报错；
3. **渲染**：用 Astro 内置的 Markdown 管线把正文转成 HTML（代码高亮、标题锚点、
   目录都在这一步生成），再套进页面模板输出。

渲染结果按「文件修改时间 + 文件大小」缓存，所以只有真正改过文章时才会重新解析。

## 为什么不用重新构建

传统静态博客需要「改内容 → 重新构建 → 部署」三步。本站做成了服务端渲染：
页面在**被访问时**才去读文件，因此后台一保存，下一次刷新就是新内容。

代价是必须有一个 Node 进程在运行（`npm start`），不能像纯静态站那样丢到对象存储就不管了。
换来的好处是写作体验接近动态博客：保存即生效，草稿也能随时预览。

## 出错了会怎样

- **表单字段不合法**：接口返回 400，页面顶部显示具体是哪一项有问题；
- **手写的 md 有语法错误**：这篇文章会被跳过，其他文章不受影响，后台首页会告诉你哪个文件哪里错了；
- **文件名重复**：保存时提示「文件已存在」，换一个文件名即可。

想手动检查全部内容，运行 `npm run check`，它会用同一套规则体检目录里的所有文件。
