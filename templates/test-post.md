如果你能在网站上看到这段文字，说明「把 Markdown 文件放进目录 → 网站自动更新」这条链路是通的。

## 这篇文件是怎么被放上来的

它原本放在项目根目录的 `templates/` 文件夹里，**这个文件夹不属于网站内容**，
所以之前它不会出现在任何页面上。被复制到 `src/content/blog/` 之后，它才成为一篇文章。

文件路径和网址的对应关系是这样的：

```text
templates/test-post.md              ->  不在网站上
src/content/blog/test-post.md       ->  /blog/test-post/
```

决定网址的是**文件名**，而不是 `title`。把文件重命名成 `my-first-post.md`，
网址就会变成 `/blog/my-first-post/`。

## 试着改一改

可以拿这篇文件做几个小实验，改动保存后回到浏览器刷新即可看到结果：

1. 把上面的 `title` 改成别的文字 —— 页面标题和列表页会跟着变；
2. 在 `tags` 里加一个新标签，例如 `tags: [测试, 自动更新, 新标签]` ——
   会多出一个 `/tags/新标签/` 页面；
3. 把 `draft` 改成 `true` —— 如果设置了管理密码，就只有登录后台的人能看到它，
   访客访问会得到 404；
4. 在下面继续写一段自己的内容，甚至贴一张图片
   （图片放 `public/images/`，用 `![说明](/images/文件名.jpg)` 引用）。

## 想当正式文章用

这篇只是模板。如果要认真写一篇，推荐用脚本生成干净的文件：

```bash
npm run new "文章标题" -- --tags Astro,教程
```

写完之后，把这篇测试文件删掉，网站就只保留你真正想发布的文章了。

> 小提醒：同一目录下不要出现**同名**的 md 文件，否则它们会指向同一个网址，
> `npm run build` 时会报重复 id 的错误。遇到这种情况，重命名其中一个即可。
